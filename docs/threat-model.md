This model is written from the attacker's side first. It is the baseline of priorities for people, AI agents and code scanners that review this repository. It describes structure, not individual defects. Report a vulnerability through the process in [SECURITY.md](../SECURITY.md).

## System summary

**Purpose.** The Concord Voice client for iOS and Android. It signs in to a Concord server that the user types, and reads and sends end-to-end-encrypted direct messages and attachments. `README.md` marks it pre-alpha: it is not in any app store.

**Components.**

- The JavaScript app: shell `App.tsx`, REST client `src/core/ConcordApi.ts`, DM socket `src/core/DmSocket.ts`, session store `src/state/session.ts`, conversation logic `src/state/conversation.ts`, and screens under `src/ui/`.
- The native crypto module, one per platform, behind one typed bridge `src/ConcordCrypto.ts`: Swift in `native/ConcordCrypto/Sources/`, Kotlin in `native/ConcordCrypto/android/`. Both build the vendored Argon2 reference C code in `native/ConcordCrypto/Vendor/argon2/`.
- The app attestation module, iOS only: `native/ConcordCrypto/Sources/ConcordAttest.swift` behind `src/ConcordAttest.ts`.
- The native shells: `ios/ConcordVoice/AppDelegate.swift` and `android/app/src/main/java/com/concordvoice/MainApplication.kt`.

**What each platform has today, from the code.**

| Property                   | iOS                                                                                                                                             | Android                                                                                                                                                                                                                                                                                                                |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Message and key crypto     | CryptoKit AES-256-GCM, Security.framework RSA-OAEP-4096 with SHA-256, Argon2id (`native/ConcordCrypto/Sources/ConcordCrypto.swift`)             | Platform JCA providers for the same algorithms, Argon2id over JNI (`native/ConcordCrypto/android/src/main/java/com/concordvoice/crypto/ConcordCrypto.kt`, `native/ConcordCrypto/android/src/main/cpp/argon2_jni.c`). The module is registered in `android/app/src/main/java/com/concordvoice/MainApplication.kt`       |
| Unlocked identity key      | Software RSA key in process memory, addressed by an opaque handle (`native/ConcordCrypto/Sources/ConcordKeyStore.swift`)                        | The same (`native/ConcordCrypto/android/src/main/java/com/concordvoice/crypto/ConcordKeyStore.kt`)                                                                                                                                                                                                                     |
| Identity key at rest       | Keychain item, `kSecAttrAccessibleWhenUnlockedThisDeviceOnly` with `.biometryCurrentSet` (`native/ConcordCrypto/Sources/ConcordKeychain.swift`) | PKCS#8 blob in `noBackupFilesDir`, encrypted by a Keystore AES key that needs a biometric for each use (the strong class on Android 11 and later), is invalidated by a new enrolment, and is refused outside a TEE or StrongBox (`native/ConcordCrypto/android/src/main/java/com/concordvoice/crypto/ConcordVault.kt`) |
| Session record at rest     | Keychain item, `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`, no prompt                                                                    | File in `noBackupFilesDir`, encrypted by a Keystore key with no user authentication                                                                                                                                                                                                                                    |

| Decrypted attachment files | Caches folder, `NSFileProtectionComplete`                                                                                                       | `cacheDir`, with no protection beyond the platform's own storage encryption (`native/ConcordCrypto/android/src/main/java/com/concordvoice/crypto/ConcordCryptoModule.kt`)                                                                                                                                              |
| Backup                     | Both Keychain items are device-only                                                                                                             | `android:allowBackup="false"` in `android/app/src/main/AndroidManifest.xml`; secrets live in `noBackupFilesDir`                                                                                                                                                                                                        |

Both platforms have native end-to-end encryption in this revision. Android differs in three ways: no attestation, no file-level protection class on cached plaintext, and identity key bytes that pass through JVM arrays whose zeroing is best-effort (stated in the Kotlin source).

**Deployment modes.** One app talks to either the hosted service or a self-hosted server. The user enters the server address at sign-in (`src/ui/SignIn.tsx`). Every socket carries the fixed origin app://concord-mobile (`src/core/socket.ts`).

**Production.** There is no production release. `android/app/build.gradle` defines only a debug signing config, and minification is off. `README.md` states that release builds are unsigned until a release key exists. `Gemfile` holds CocoaPods only; there is no store-upload tooling in the repository.

**Build and release workflows.** `.github/workflows/required-pr-build.yml` is the required pull-request gate; it calls `.github/workflows/pr-ci.yml` and `.github/workflows/osv-scanner.yml` at a pinned commit of the default branch. `.github/workflows/mobile-native.yml` builds unsigned iOS and Android binaries and is advisory. Scanners: `.github/workflows/semgrep.yml`, `.github/workflows/codeql.yml`, `.github/workflows/secret-scanning.yml`, `.github/workflows/ioc-scanning.yml`, `.github/workflows/sonarcloud.yml`, `.github/workflows/scorecard.yml`. Supporting workflows: `.github/workflows/build.yml`, `.github/workflows/eslint-sarif.yml`, `.github/workflows/codeql-pr.yml`, `.github/workflows/license-check.yml`, `.github/workflows/scanner-baseline.yml`, `.github/workflows/sonar-main.yml`, `.github/workflows/audit-allowlist-expiry.yml`, `.github/workflows/labeler.yml` and `.github/workflows/workflow-validate.yml`. Two scheduled workflows open pull requests with an organisation App token: `.github/workflows/sync-tooling.yml` and `.github/workflows/refresh-ioc-list.yml`.

**Tests.** Jest suites in `src/__tests__/` mock the native bridge. Native tests are in `native/ConcordCrypto/Tests/` and `native/ConcordCrypto/android/src/test/`. `scripts/native-runtime-probe/` is a test-only app entry that the default app never imports.

**Not built.** The code has no push notifications, no deep links or universal links, no WebView, no voice or video, and no server or channel screens. `ios/ConcordVoice/Info.plist` declares no URL scheme, `ios/ConcordVoice/ConcordVoice.entitlements` holds only the App Attest environment, and `android/app/src/main/AndroidManifest.xml` has one launcher intent filter and declares one permission, INTERNET. `README.md` records that the video library adds ACCESS_NETWORK_STATE to the merged manifest.

## Assets

Ranked by value to an attacker.

1. **The identity private key** (RSA-4096). It unwraps every conversation key the account can read. It exists unlocked in native process memory for the whole signed-in session, and at rest behind biometrics.
2. **The account password.** It signs in to the server and is the input to the Argon2id wrap of the identity key. It passes through JavaScript memory (`src/state/session.ts` keeps it between the password step and the MFA step) and is sent to the server by `login` in `src/core/ConcordApi.ts`.
3. **Conversation keys** (AES-256, one per key epoch), held natively by handle.
4. **Decrypted content.** Message text lives in JavaScript memory and the React tree. Decrypted attachments are files in the app's cache folder.
5. **Session credentials.** The refresh token, session id and machine id in the stored session record; the access token, attestation token and WebSocket ticket in JavaScript memory.
6. **The App Attest key** (iOS, Secure Enclave), which lets the server tell the genuine app from another client.
7. **Integrity of what ships.** The JavaScript bundle, the native binaries, the dependency lockfiles, and the future release signing keys.
8. **CI credentials.** GitHub Actions holds two values for this repository: `SONAR_TOKEN`, read by `.github/workflows/sonarcloud.yml` and `.github/workflows/sonar-main.yml`, and `PUBLIC_MIRROR_APP_PRIVATE_KEY`, read by `.github/workflows/refresh-ioc-list.yml` and `.github/workflows/sync-tooling.yml`.
9. **Metadata.** The server address, user id, conversation list, client version and platform.

## Security objectives

A change must keep each of these. Each is written so a reviewer can test it.

1. No bridge method returns key bytes to JavaScript. Results are handles, ciphertext, a public key, or decrypted message text (`src/ConcordCrypto.ts`).
2. There is no JavaScript crypto fallback. Without the native module, `native()` throws and sign-in fails.
3. The identity key at rest is readable only after a biometric check, never leaves the device, and becomes unreadable when the biometric set changes. Android refuses to store it without secure hardware.
4. The session record never holds an access token or key material, and only its five known fields are read back (`parsePersisted`, `resume`).
5. Every network target is https, except loopback. Session headers go only to the configured server base: `mediaSource` checks the URL prefix, `attachmentRequest` accepts only a UUID, and `request` sends no ambient cookies.
6. A native attachment download refuses redirects, any status but 200, and any byte past the caller's cap.
7. Decryption fails closed. A failed attachment decrypt removes its output file (`native/ConcordCrypto/Sources/ConcordCrypto.swift`, the Kotlin `ConcordAttachments.kt`). A well-formed message that does not decrypt is added to the conversation as unreadable, and no read receipt is sent while the newest line is unreadable (`decrypt`, `settle` and `start` in `src/state/conversation.ts`).
8. Decrypted files exist only in the attachment cache folder. The folder is emptied at sign-out, at session expiry and at every launch.
9. Native rejections carry a fixed code and a fixed message (`native/ConcordCrypto/Sources/ConcordCryptoModule.swift`, `native/ConcordCrypto/Sources/ConcordAttestModule.swift`, the Kotlin `ConcordCryptoModule.kt`). `ApiError` carries a status and a code only. The app and native sources hold one log call, which prints a native error code (`src/state/session.ts`). No change may log message text, keys, tokens or server bodies.
10. Only Argon2id with the fixed parameters is accepted for the identity wrap. An RSA key must be 4096 bits in the exact expected encoding.
11. On Android only the launcher activity is exported, backup is off, and the file provider is not exported.
12. Sign-out releases every native handle and deletes both stored items; a failed delete is retried and then reported to the user.
13. Third-party actions are pinned by commit hash. Pull-request code never runs in a job that holds a secret. Scanner rules for the required build come from the protected revision, not from the pull request.

## Weakest ground

Ranked. Scans and reviews start here.

1. **One password, two jobs.** The password authenticates to the server and derives the key that wraps the identity key. End-to-end confidentiality against the operator rests on the server not keeping what it receives. There is no second layer in this client.
2. **The whole JavaScript bundle is inside the crypto boundary.** Any code in the bundle can decrypt with any live handle, ask for a key to be wrapped to any public key, and name any https URL and headers for a native download. Every JavaScript dependency therefore sits beside the keys.
3. **The server asserts what the cryptography does not bind.** Public keys, epoch labels, sender names and message order are taken from the server. Message blobs carry no associated data. No screen lets a user verify a peer's key.
4. **Transport trust is the platform trust store alone.** The server is user-chosen, so a build-time pin list cannot work; nothing remembers a server's identity between sessions. On Android the OS-level cleartext rule is a default of the build plugin: no file in this repository sets the release value, so a plugin change or a new build type could alter it silently.
5. **Complex parsers run on attacker-chosen plaintext.** Platform image, video and document decoders run in the process that holds the unlocked key. The hand-written DER reader, the attachment envelope classifier and the vendored C key-derivation code parse server-supplied bytes. Method: OWASP MASTG platform and code tests, plus fuzzing of the two hand-written parsers against the shared vectors in `native/ConcordCrypto/Tests/attachment-vectors.json`.
6. **The unlocked session has no inner lock.** The identity key stays in process memory until sign-out. There is no app lock, no inactivity timeout, and no screen-capture protection. `docs/plans/2026-11-04-android-crypto-port-design.md` lists app lock as later work.
7. **Android has fewer layers than iOS.** No attestation, no file-level protection on cached plaintext, and key bytes in managed memory. The client states its own platform in a request header (`headers` in `src/core/ConcordApi.ts`), so a server that requires attestation must either refuse Android or trust that statement.
8. **The release path does not exist yet.** Signing, store upload, minification and release provenance are all future surface. Each will arrive as new, unreviewed ground. Code owners cover CI and tooling paths, not the app or its native crypto. The native crypto tests run in an advisory workflow, not in the required gate (`README.md`).
9. **A long-lived session credential sits behind device unlock only.** `login` always asks for a remembered session, and the stored record needs no user presence to read. `.gitar/review/mobile.md` records the reason: planned background refresh must read it.
10. **Surface carried ahead of its feature.** Bridge and client methods exist with no screen that uses them. `docs/adr/0047-mobile-client-framework-and-native-boundaries.md` plans push, incoming calls and media, each of which adds a new untrusted input.

## Assumptions and unknowns

- **Server prerequisites.** The server must list the origin app://concord-mobile among its allowed origins (`README.md`). Token rotation, ticket issue, attestation verification, rate limits and minimum-version checks are server behaviour and are out of scope here.
- **Device prerequisites.** iOS deployment target 16.0 (`ios/Podfile`); Android minimum SDK 26 (`android/build.gradle`). A stored sign-in needs an enrolled biometric, and on Android a TEE or StrongBox; without them the user signs in with the password at each launch.
- **Provided fact: Android cleartext policy.** The React Native Gradle plugin that ships with the React Native version pinned in `package.json` sets the cleartext placeholder in `android/app/src/main/AndroidManifest.xml` to false for the release build type and to true for the debug build types. The maintainers supplied this fact from a read of the plugin. It is the plugin's default; no file in this repository sets it.
- **Exclusions.** The React Native framework, third-party packages, the vendored dependency copies and the operating systems were not reviewed. This was a static read; nothing was built or run.
- **No release exists.** Signing, distribution and store review are undefined. Review this model again before the first release.
- **Document and code disagree.** `README.md` says the Android native crypto module is absent in its native-validation section (`README.md:257`) and in its "Not built yet" list (`README.md:315`), while its introduction (`README.md:34`) says encryption runs natively on both platforms. The code has the module and registers it. The code wins; the platform table above reflects the code. `.gitar/review/mobile.md` says the repository is private and has no SonarCloud workflow; `.github/workflows/sonarcloud.yml` exists.
- **Privacy roles.** Per the published privacy policy: when self-hosted, the operator is the data controller; for the hosted service, Concord Voice LLC is the controller; users must be at least 16.
